# SCOPE — mini-amc (v1)

A mini-clone of Auto-Multiple-Choice (AMC) based on Typst, developed by vibe-coding.
The whole project is in English: code, docstrings, comments, documentation, CLI messages, data formats, commit messages.

## v1 scope

Included:

- MCQ, single-answer (circle bubbles) or multi-answer (square bubbles, several `correct: true` choices): 1 pt iff the checked set equals the expected set.
- Open (free-text) questions graded by the teacher on the paper copy, before scanning: the copy shows a free area + a gray grader area with lettered grade boxes A, B, … (box value = letter index, 0..max_points); the OMR reads the blackened box and the score is its value; ungraded (no box) → `needs_review`, still correctable in the review UI.
- Named grading schemes (``BAREMES`` in `grade/notes.py`), chosen per exam in ``data/config.json`` (written by `generate`, default ``v1``), overridable with ``--bareme`` on `grades`/`web`: ``v1`` = 1 pt iff the checked set equals the expected set, else 0; ``amc`` = +1 per correct checked, -1 per wrong checked, floored at 0 per question. Open questions score their box value (0..max_points) under all schemes. ``notes.csv`` has a ``bareme`` column.
- Personalized PDF copy generation (question and choice shuffling, seeded and reproducible).
- Self-contained Typst template: bubbles to check directly under each question, 4 black alignment squares in the corners of every page, 1 QR code at the top right of every page.
- 100% local OMR reading of scans (OpenCV): corners → homography → QR → bubbles.
- Review web UI (FastAPI) for ambiguous cases.
- Grade export to CSV.
- Optional nominative CSV (``--students``): flexible on the format — delimiter auto-detected, link column (``--students-id-column``, default ``copy_id``, e.g. ``Numéro étudiant`` in a Moodle export) provides the copy ids, name column(s) (``--students-name-columns``, default ``name``, comma-separated) form the display name, all other columns ignored. Row count must equal ``--copies``. Stored locally as ``data/students.json``, joined into ``notes.csv`` (``student`` column) and shown in the review UI. Student data stays 100% local.

Out of scope for v1:

- Custom grading formulas (per-question expressions à la AMC).
- Moodle / LMS export (the import direction is covered by the flexible `--students` CSV).
- Email sending.
- Rich UI.

The rollout backlog (nominative CSV link, grader-blackened free-text fields) is now implemented — see NOTES.md.

## Technical decisions (acted)

- Zero external Typst packages (no suiji, no tiaoma, nothing from the Universe):
  - random shuffling is done in Python (seed);
  - QR codes are PNGs generated by Python (lib `qrcode`) and included via `#image()`;
  - bubble positions are extracted in D2/D3 via `typst eval` on `#metadata(...)`.
- On EVERY page: 4 black alignment squares in the corners + 1 QR code (text content `copy:XXXX|page:N`) at the top right.
- Typst CLI pinned to v0.15.1 (official binary); `src/mini_amc/template/typst.toml` contains `compiler = "0.15.1"`.
- Typst 0.15 syntax: compound alignments are written `top + left` (not `top-left`).
- Python stack pinned exactly in `pyproject.toml` (`==`) + committed `uv.lock`: opencv-python-headless==5.0.0.93, numpy==2.5.4, pillow==13.0.0, qrcode==8.2, PyYAML==6.0.3, fastapi==0.162.5, uvicorn==0.54.0.
- QR reading on the OMR side with `cv2.QRCodeDetector` (no pyzbar, no system dependency).
- 100% local data: scans of answer sheets (student data) never go to the cloud.
- Language: everything in English (code, docstrings, comments, docs, CLI messages, statuses, commit messages).
- Docstrings required on the public API of `.py` files (Google convention, lint ruff `D` + `pydoclint`): they describe the "what" (contract: args, returns, errors). Minimal inline comments in `.py` and `.typ`: only when the "why" is not obvious (non-trivial decision, workaround). Design decisions go in `SCOPE.md` / `README.md`.

## File formats

| File | Role | Produced by |
| --- | --- | --- |
| `src/mini_amc/examples/bank.example.yml` | Question bank (example, copied by `mini-amc init`): MCQ (`choices` + one `correct`) and open questions (`type: open`, `max_points`) | manual input |
| `src/mini_amc/examples/students.example.csv` | Nominative list (example), header `copy_id,name` | manual input |
| `src/mini_amc/examples/students.moodle.example.csv` | Moodle-style export (example): `;`-separated, link column `Numéro étudiant` | Moodle/LMS export |
| `data/copy_XXXX.json` | One copy: shuffled questions/choices, keys A/B/C… | `gen/generate.py` |
| `data/copy_XXXX.pdf` | The printable copy (Typst template + `copy.json` + `qr-{page}.png`) | `gen/generate.py` via `typst compile` |
| `data/build/XXXX/` | Typst build directory of one copy (`main.typ` + `copy.json` + `qr-N.png`) | `gen/generate.py` |
| `data/positions.json` | Positions per copy (indexed by `copy_id`): `bubbles` (MCQ) + `gradeboxes` (open questions, with `value`), extracted via `typst eval` on `#metadata(...)` | `gen/generate.py` |
| `data/answers.json` | Correct answers per copy (answer key) | `gen/generate.py` |
| `data/students.json` | `copy_id` → student name (from `--students`, optional) | `gen/generate.py` |
| `data/omr_results.json` | OMR results: `scans` (per scan: status `ok` / `needs_review` / `unread`, copy_id, page, questions) + `copies` (multi-page aggregate per copy_id: status `ok` / `needs_review` / `partial` / `unread`, pages, questions with page) | `omr/read_scans.py` |
| `data/annotated/` | Straightened and annotated scans (markers, QR, detected bubbles) | `omr/read_scans.py` |
| `data/corrections.json` | Manual corrections from the review UI: `{copy_id: {qid: [keys]}}` | `web/app.py` (D7) |
| `data/notes.csv` | Grade per copy: `copy_id,student,status,score,score_max` (`student` empty without `--students`) | `mini-amc grades` (D8) |
| `data/notes_detail.csv` | Question-by-question detail: `copy_id,qid,type,page,checked,correction,expected,point,needs_review` (`type` = `mcq`/`open`, `expected` = key or `open`) | `mini-amc grades` (D8) |
